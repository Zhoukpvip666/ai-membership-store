## 目标与优先级

用户当前优先级是尽快让客户访问商品展示页。当前下一任务改为**商城前台首发的应用侧收尾**，经营概览真实数据继续后移。

首发沿用已经合并的商城设计和功能：游客浏览商品列表、详情与主图；点击购买后登录或注册，再继续已有下单流程。客户的订单、订阅和个人中心继续使用现有权限边界。收款仍由管理员人工核实，履约仍为人工处理。

“优先商品展示页”不改变已有购买功能。若之后需要改为纯展示站、取消购买入口或改变支付方式，另行讨论该产品决定。

本任务结合前台正式展示修正与 [T23.1 应用配置适配](28-production-deployment-design.md)。它不表示 T23.2–T23.5 部署准备和实际发布已经完成；部署证据继续按原计划记录。

## Codex 本次实现范围

提交一个可审查的应用实现 PR；先核对最新主线，避免覆盖本任务草案之后的变更。预期涉及前台布局、路由标题、登录/个人中心文案、公开店铺配置、后端环境和请求配置、启动/停止逻辑，以及相关测试与文档。

### 客户看到的页面

- 延续 PR #45/#46 的视觉与布局，保留桌面三列、手机两列商品卡片和现有商品详情结构。修正验收中发现的溢出、图片失败展示或购买入口问题。
- 更新客户路径内的预览、本地工具和过时阶段提示。页面标题、品牌和页脚使用一致的店名。
- 为游客提供专用只读公开店铺配置，响应按白名单仅包含本次需要的 `storeName`。使用现有 AppSettings 作为数据源；前台公开状态与管理员设置状态分开。管理员邮箱、收款说明、收款码及其存储信息不能随此接口公开。
- 店名加载有合理的加载/失败回退；新开匿名窗口可读到当前店名。管理员仍通过受保护的原设置接口管理店名。
- 保留“立即购买”、安全登录/注册续接、已有订单与订阅入口；管理控制台仍仅向 ADMIN 显示。个人中心的说明只承诺已经实现的能力。
- 演示与验收使用独立测试商品和图片；真实商品内容、价格和上架状态在实际发布验收中核实。

### T23.1 应用生产配置

以 [生产设计的 T23.1](28-production-deployment-design.md) 为约束完成应用侧适配，重点覆盖：

- 明确区分本地开发与生产配置。生产使用经过校验的 HTTPS origin；拒绝带凭据、路径、查询、片段、错误主机或占位值的配置。开发环境继续支持原有本机运行方式。环境示例只使用占位值。
- 分离 API 运行凭据与管理员 bootstrap/迁移凭据。保持拟定部署拓扑中的 API、数据库 loopback 绑定；API 绑定本机是该拓扑的设计，不应为了公开访问而直接暴露 API 或数据库端口。
- 根据同机 Caddy 拓扑限定可信直接代理，保留准确的客户端限流键。不能设置无条件代理信任，也不能直接相信浏览器提交的转发头。实际 Caddy 头处理和完整代理链验证在部署模板/演练中形成证据。
- 保留 HTTPS 下的安全 Session cookie、精确 Origin 校验、请求头校验、角色/ACTIVE 状态检查与本人记录权限。登录、退出、邀请以及注册后的购买续接按正式 origin 工作。
- 按 T23.1 验证现有两个定时任务的停止与数据库断开顺序，确保关闭时处理正在执行的任务；保持单 API 实例及现有订单超时、订阅到期业务规则。
- 启动不自动迁移或 seed。独立测试需要新建数据库时，使用合成数据并保留已提交的历史迁移 SQL。

## 与发布工作的衔接

这份任务单为一个应用实现 PR 准备范围。应用通过审查后，按 T23.2–T23.5 准备并验证实际部署：真实目标服务器与域名、HTTPS 和 SPA/API 路由、数据库迁移状态、商品主图与收款码的独立持久化目录、协调备份，以及桌面/手机访问验收。

本次没有核实服务器现状、真实商品内容或当前部署版本。历史 VPS 审计不能充当这些事实的当前证据。实际发布仍需把目标与操作具体化；现有生产设计对共享服务、真实数据和恢复点的约束保持适用。

经营概览、订单续费、邮件通知、供应商接口和在线支付不属于本次首发收尾。不要为完成这些未来功能延后当前商品展示页的上线准备。
